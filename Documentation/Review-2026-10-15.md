## Changes

- Observe uses a continuous scroll list, requests server rank ordering, and orders loaded
  rows by the stronger player. Player ranks, move counts, board size and time controls
  replace the displayed game ID. Metadata comes from list snapshots; Refresh reloads it.
  Batches merge duplicate game IDs, stop at the end, retain existing rows after failures,
  and reject late replies after refresh or logout. Unknown metadata is shown as unavailable.
- Challenge Cancel is now a visible standard button on the left, with Escape support;
  green Issue stays on the right. Red is reserved for destructive actions, following
  [Apple's button roles](https://developer.apple.com/design/human-interface-guidelines/buttons).
- The visible upper 2D lid moves downward to halfway between the board edge and grid.
  Its horizontal position is unchanged; the calculation accounts for transparent asset padding.
- Pass and Resign are adjacent. Resign opens an explicit warning and only targets the
  game that opened the warning. Changing games, losing permission/connection, or leaving
  the panel dismisses it. Service-level checks also reject stale/wrong-game commands.
- Pass and stone placement use the same readiness and engine-turn checks. Pass is blocked
  during handicap placement, history review, scoring, disconnection and state refresh.
  A Return to latest move button helps players who have rewound the game.
- Undo has a visible decline action and an outgoing-request cancel action. Empty-game,
  repeated, stale and mismatched requests are blocked. Game/connection changes clear old
  undo state. Responses still come from OGS; the UI does not invent an accepted undo.
- A disconnection retains the active-game panel and offers Reconnect. Errors are visible.
  Opening another game clears old player names/ranks, clocks, turn and handicap metadata.
  Missing clocks show a placeholder instead of looking like zero time remaining.
- Chat submission retains a draft when dispatch is unavailable, rejects blank messages,
  clears drafts on game changes, and releases the typing flag when the editor disappears.
  Debug logging of the typed message and its hexadecimal bytes was removed.
- Login guards repeated Return submissions and supports Escape. Cancelling an in-progress
  login uses the existing logout/generation fence so its delayed result cannot reconnect.
- Challenge settings reject invalid time controls, durations, handicap and rank ranges.
  Numeric minute/second editing is bounded against overflow. Native field editors suppress
  board navigation shortcuts. A submitted form offers Close; closing does not retract the
  already-sent request. A late result cannot dismiss a newly opened form.
- A forbidden challenge-cancellation response leaves the challenge visible and explains
  that cancellation was not confirmed; only success or a missing challenge removes it.
- SGF export captures names from the requested game, avoids duplicate downloads, reports
  download/write failures, and does not open a save panel after switching away.
- Continuing a review position into an existing local game now asks before replacing it.
- Switching away from 3D releases the SceneKit scene and interaction closure. No change
  was made to the rendering rate or the five-per-second slider preview limit.

## Observe and AI layout follow-up

The Observe browser no longer repeats “Logged in as …”; account identity remains in the
main toolbar. Its live-list response was checked anonymously against OGS: the compact
Socket.IO rows contain `move_number` and estimated `time_per_move`, but no complete time
control. A read-only game detail GET supplies `gamedata.time_control`; the REST top-level
`time_control_parameters` can also be a JSON-encoded string. Both formats are supported.
Visible rows fetch details with at most three concurrent requests. Reappearing rows reuse
results; Refresh retries failures; disconnect/logout/refresh invalidate late completions.
These reads never join games or use/cancel the active board's reconciliation reader.

Observed game-over subtitles now read “Alice [Black] wins” or “Bob [White] wins”, including
resignation/timeout outcomes. Draws remain draws; the existing Final Score text is retained.

AI always stays to the right, in both renderers. The 2D board group uses its allocated width
and relinquishes surplus left margin to analysis. The graph and analysis summary share a
scrollable column with room beneath them. At window widths of 1500 points or more, the
320-point game panel also has reserved space. With AI enabled in narrower windows, that
dismissible panel overlays the AI column; closing it exposes the graph. AI never relocates
below the board. The 3D viewport adjusts its framing to keep the board and both capture
lids inside its allotted area; saved camera position/zoom settings are not rewritten.

## 3D backdrop and global sound control

The shared workspace no longer puts a 2D tatami texture behind the inset 3D viewport.
SceneKit, its native view and the surrounding 3D workspace use one background color;
2D retains tatami. No board geometry, camera preference or AI-column sizing changed.
AnalysisLayout now checks pixels in the margins/AI column against the rendered scene
background and confirms that 2D remains textured. It composites the actual SceneKit render
into the captured UI for visual review, with logical-point coordinates so Retina scaling
is applied only once.

The speaker is in the global toolbar immediately before account details. It is available
in every mode and board view. Click toggles mute; holding for 0.45 seconds or right-clicking
opens the volume popover. A native button retains accessibility and suppresses its release
action after a hold, preventing an accidental mute toggle. The popover includes a master
slider, percentage/muted indication and an explicit Mute/Unmute button. Raising the slider
unmutes; clicking at zero restores the last nonzero master level.

Master volume defaults to 100% and multiplies, rather than replaces, the existing separate
stone/voice levels. The stored mute and master level use the app's own preference domain.
Previously mute affected voice announcements but not AppModel's stone/capture players.
Both paths now honor it. Muting or setting master volume to zero stops active players;
a generation check also invalidates pending 3D click/capture closures, even if the user
unmutes before their delay expires. No old muted clip resumes on unmute.

Verification: 215 unit tests and four network-denied UI suites passed: SoundControl,
AnalysisLayout, PlaybackAudio and Modes. SoundControl exercises actual native short and
long mouse presses, right-click, the popover slider, saved-volume restoration, balanced
