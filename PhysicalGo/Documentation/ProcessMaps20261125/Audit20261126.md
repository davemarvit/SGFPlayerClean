## Findings requiring explicit disposition

### A1 — Lease expiry inside a raw write can recursively acquire the write lock

**Confirmed offline against 40adedf; repair requested from root.**

`GatedController.command` reaches `LeaseGate.send`, whose `before_write` validator invokes `poll()`. `Controller._write` invokes that validator while holding its non-reentrant `write_lock`. If the lease expires while acquiring the write lock, `poll()` calls `_revoke()`, which immediately sends OFF through the same controller. That nested `_write('OFF')` attempts to acquire the already-held write lock while the operation also holds the gate lock. The watchdog/coordinator cannot acquire that gate to resolve the stall.

The reproduction uses the actual `Controller._write` and `LeaseGate.send`, bypasses the hardware-opening constructor, mocks every possible OS write and substitutes a trip-on-reentry lock for a blocking lock. Result: `PSW1591 → OFF → REENTRANT_WRITE_LOCK_ATTEMPT`. No serial port, camera or app is opened. Existing adapter fixtures use a fake raw writer without the real write lock, so they do not exercise this cycle.

Minimal design requirement: a callback executing under the raw write lock must not initiate another transport write. It may reject the pending command and revoke logical authority; the existing stop owner must send OFF after the raw lock has been released. Preserve immediate cancellation, the existing lease and bounded write semantics. Replacing the lock with a reentrant lock alone is not a complete protocol solution because a partial command and nested OFF must not interleave bytes.

### A2 — Adequate admission and wire publication are different boundaries

**Confirmed wire behavior in an offline reproduction against40adedf; reviewer contract/repair disposition pending.**

The new `_adequate_guard` correctly checks the exact optical/motor evidence at `gate.accept_result → self.feedback`. However, `BridgeRuntime._publish` subsequently snapshots a four-field feedback tuple, writes a temporary JSON file outside the gate, and rechecks generation/identity/feedback before renaming it. It does not carry the optical evidence deadline in that tuple. The same adequate tuple can also be republished with a fresh `updatedAtUnix` while the next normal held observation is running.

The native cue consumer checks matching identity, illuminated adequate state and status age; it receives no sample optical timestamp in this version. Consequently “fresh heartbeat describing last accepted state” and “fresh adequate evidence” can be conflated. A delayed first adequate delivery can consume the once-per-move cue after the underlying sample's original acceptance window.

An actual `_publish` reproduction (fake backend, no runtime start, isolated temporary files) produced adequate/illuminationConfirmed with optical sample age850ms and status age550ms after a delayed first file write. A later same-tuple heartbeat had optical age1.10s and status age0. The request lease remained valid. Script: `/Users/Dave/Documents/SGF PLayer/work/physical-go-process-audit-20261126/reproduce_adequate_wire_age.py`.

Required disposition: define adequate as either historical state or current evidence. For current evidence, carry a scoped, immutable evidence receipt through actual status replacement and native consumption, preserving original timestamps. Keep historical last-good information separately if useful for presentation. Rechecking only the in-memory save does not cover file latency. This proposes no new numerical deadline and no wider evidence allowance.

## Boundaries retained by the candidate

- **One retry owner:** `_with_optical_recovery` owns the entire held step and adequate publication. Nested observations share its controller/session/telemetry/target/token scope. Only the operation's acknowledged exact-next-generation cooling RS may advance that scope.
- **One finite work ledger:** initial acquisition and recovery share 150 seconds active work and 25 local correction plans; initial predicted coarse waypoints retain their separate cap and run at most once. Verified adequate waiting pauses active-work accounting, never leases, camera/thermal ages or illumination time. Each recovery's 30-second provisional wall cap cannot restart through nested retries.
- **Two meanings of acceptance:** a fresh, correctly measured spot may be published/persisted as a historical anchor even when it misses the requested target. Target adequate requires the independent ≤0.20-cell test and current publication proof. Publication71/frame35013 demonstrates this distinction.
- **Crossing is not immediate motor drift:** first outside-band observation withdraws adequate and requests a completely newer full-board confirmation. A second outside result uses contained correction; a later independent held check is required before adequate. This handles measurement variation without widening the accuracy band or inferring physical movement from a scalar error alone.
- **Typed expiry is not unsafe-clearance recovery:** an expired computation result is discarded. Current independent safety/identity/pose and newer full-board pixels are required. Unknown hand, ambiguous spot, invalid clock, unrelated generation or transport faults remain outside that retry path.
- **Dark geometry assessment grants no light authority:** invalidate old current geometry, DARK before assessment (including PREPARE state), assess only the exact rejected data, then qualify three newer dark frames and validate the replacement before assignment. A retained historical spot/H is only a first-light containment hint. Fresh actual pose and optical measurement precede correction.
- **Optional lit renewal is scheduling, not permission:** unmasked fixed-anchor proof remains required. A measured laser exclusion cannot establish target visibility, empty intersections or hand clearance. The optional 100ms computation allowance may defer; the original certificate is not retimestamped. The existing 2-second remaining-geometry reserve and finite light interval force dark fallback.
- **Recognition receipts are not clearance:** any future qualified EMPTY receipt must identify its frame/context/position evidence and invalidate on relevant change. It cannot clear hand/unknown visibility, establish legality, accept a new stone or complete capture removal by history alone. Final producer/consumer source remains pending at this audit checkpoint.

## Optimization opportunities without new limits

1. **Measure waits separately from computation.** Existing results demonstrate millisecond temporal-check cost, roughly half-second optical sample ages, repeated five-frame acquisition and command/flush waits. Capture→analysis→PNG→collection→post-image pose→renewal→gate wait→wire replacement→native consumption should share one correlation identity. Attribute p50/p95 and first rejected stage before changing cadence or transport.
2. **Keep an already accepted beam when proof remains current.** The initial accepted-light promotion already removes the earlier mandatory DARK/PREPARE handoff; retain its finite original light origin. Do not recreate a light command to produce audio. Quantify preparation cycles and indication latency on comparable travel distances.
3. **Schedule optional work using remaining evidence life.** Deferral is preferable to spending the last valid milliseconds on a certificate the current observation does not need. Measure successful renewal rate, deferred work, dark fallback frequency and time spent in each; keep source capture time and final commit checks unchanged.
4. **Reuse authenticated identities and geometry, not authority labels.** Consolidate evidence receipts and their invalidation reasons across adapters before deleting checks. Native grid, temporal geometry, current spot, motor pose, physical-wood containment and legal-board confirmation answer different questions.
5. **Fix recognition assignment rather than producing more reset frames.** The earlier 25.418s R16 delay had 130 ambiguity resets despite fresh frames. A narrowly qualified EMPTY receipt may resolve an assignment cause, but exact delayed pixels were absent; retained-frame and adversarial controls cannot retroactively prove that incident fixed.
